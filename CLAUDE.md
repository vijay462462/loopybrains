# Loopy Brains (loopybrains.com)

Static PWA for RGUKT AP students (other colleges can be added), built by a non-technical student founder (Vijay). **Keep explanations in plain, step-by-step language and say which website or console each step happens in.** The user can only be guided through consoles by screenshot and cannot paste secrets here. Never ask for or print secret keys.

**Brand:** renamed from "The Campus Loop" to **Loopy Brains** (user-facing text only). Logo (chosen by the owner from five models): an **LB monogram** (monoline "LB" in warm white) inside an open coral loop with a dot, on deep teal; sources in `docs/brand/loopy-brains-*.svg`, exported to `docs/icon*.png`, `favicon-32.png`, `apple-touch-icon.png`, the share banner and `android-app/assets/`. **The in-app AI search and answer engine is now called "Loopy AI"** (it was "Loopy Brain", singular); the brand is "Loopy Brains" (plural, matches the domain). Loopy AI has its own screen (`brandSpin()` and `.bsc-*` in `docs/app.js` and `docs/style.css`) that shows the LB logo with the coral loop turning while it thinks, and the small caption "Loopy AI · your 24×7 study partner". Wordmark is LOOPY over BRAINS.

Features: class board (doubts, ideas, clubs, challenges, jobs, market, GATE), Loopy AI (knowledge-pack search and answer engine, works without sign-in), Loop Bot, daily quiz and streaks, Study Lab and tools, college data, Plus (paid) plan, push alerts.

## Architecture
- **Frontend**: plain JS/CSS/HTML in `docs/` (no build step, no framework), served by GitHub Pages at loopybrains.com (`docs/CNAME`). Entry `docs/index.html`, logic `docs/app.js` (~1 MB, one big file), styles `docs/style.css` (~350 KB, **many stacked override layers; the last rule wins**), config `docs/config.js`. Loopy AI lives in `docs/brain-*.js`; first-run splash in `docs/splash.js`.
- **Service worker** `docs/sw.js`: cache name `spark-vNNN`. Every module import in `docs/index.html`, `docs/sw.js`, `docs/admin.html` and `docs/colleges.html` carries `?v=NNN`. **Bump all of them together (currently 501) whenever a cached file changes**; `scripts/check.sh` fails if they disagree. Also bump the number in this file.
- **Backend**: Firebase project `doubt-desk-e6f39` (Firestore, Auth anonymous sign-in, Storage). Rules in `firestore.rules` (deny by default, every collection listed; `firestore.rules.open` is an emergency rollback only). Cloud Functions in `functions/index.js` (Razorpay payments and webhook, Anthropic key for AI answers, push, SMTP email; CORS allow-list `ALLOWED_ORIGINS`). Functions run on **Node 22** (`firebase-admin` 14 modular imports, `firebase-functions` 7, `nodemailer` 10, lockfile committed).
- **App Check**: web uses **reCAPTCHA Enterprise / "Fraud Defense"** (`docs/config.js` `appCheck: { siteKey, provider: "enterprise" }`; all three Firebase apps show "Fraud Defense", so `"v3"` gives a 400). Native Android uses Play Integrity via `@capacitor-firebase/app-check`. `docs/app.js` (~line 569): native + plugin present → plugin; browser → reCAPTCHA; native without plugin → skip App Check entirely. **Never fall back to reCAPTCHA when native.** Everything is in *monitoring* mode, not enforced.
- **Android app** `android-app/`: Capacitor 6 WebView wrapper that loads `https://loopybrains.com/` (`capacitor.config.json`, `allowNavigation` for loopybrains.com and www). Package `com.thecampusloop.app` (cannot change after install). Built by `.github/workflows/build-android.yml` (debug APK, artifact `Loopy-Brains-apk`, runs on manual dispatch and on pushes to `main` touching `android-app/**`). `patch_android.py` adds FLAG_SECURE; the workflow writes `google-services.json` from the `GOOGLE_SERVICES_JSON` secret. Launcher icons come from `android-app/assets/` (`@capacitor/assets`).
- **Other**: `supabase/schema.sql` + `tools/export-firestore-to-sql.mjs` (migration prep), `tests/` (packs test, rules tests, e2e, tools test), `scripts/check.sh` (syntax of all scripts, versions agree, data audit, packs check), `scripts/*icons*` (icon builders), root docs `SETUP.md`, `SECURITY.md`, `APPCHECK.md`, `RAZORPAY.md`, `OWNER_CHECKLIST.md`, `BRAND.md`, etc.

### UI system (what to know before touching CSS or layout)
- **Palettes**: `:root[data-palette="…"]` variable sets, each with light, dark and black versions; chosen with the header colour button (`PALETTES` in `docs/app.js`, saved as `dd-palette`). **Teal and coral (`tealcoral`) is the default** (deep ocean teal, coral accent, cool off-white; its block is at the end of `docs/style.css`; it re-points `--gold`, `--gold-2`, `--gold-ink` and `--gold-dark` to coral so every "gold" accent follows), then Emerald (green and gold), Midnight (indigo and gold), Royal, Burgundy, Obsidian and others. Use the variables (`--paper`, `--sheet`, `--ink`, `--muted`, `--line`, `--accent`, `--accent-soft`, `--btn`, `--shadow`, `--gold`, `--gold-2`) instead of hard-coded colours. Palette selectors beat plain `:root` rules, so add new colours inside the palette block.
- **Layouts** (all CSS, same DOM): **one model everywhere.** Phones ≤700px = compact rounded top card (logo, college chip, colour/bell/theme buttons, segmented tabs), Home block, rounded cards, floating bottom nav. Laptops and tablets ≥701px use the same model, just wider (centred container max 1120px, sticky top card, centred floating bottom nav, subject chips, posts and answer panel side by side from 901px). The earlier left-sidebar and grid-header laptop layouts were removed; do not bring them back unless the owner asks.
- **Icons**: thin line SVGs, not emoji, in the header. `icon(name, size)` helper and `ICONS` map near `el()` in `docs/app.js` (static trusted markup parsed with `DOMParser`); older `svgIcon()`/`ICON_PATHS` serve the bottom nav.
- **Home block** (`renderHome()` in `docs/app.js`, `#homeBento` in `index.html`): greeting, gold "Ask a doubt" button and four tiles on top of the Doubts feed.
- **First run**: welcome splash (`#splash.sp2`; shows once per browser session, flag `sessionStorage dd-splash`; its small print shows the app version, e.g. `v478`) then `showWelcome()` steps (about, college, name, interests, ready). The About page opens about 0.1 s after "Join my campus". **About is strict**: Continue starts disabled and `go()` refuses to leave About until the text was really scrolled to the end (a short text unlocks after 5 s) and the age/terms box is ticked (pre-ticked if `dd-terms` exists); taps within 1.2 s of a step appearing are ignored. **Pop-ups run one at a time**: the college welcome card (`showCollegeReveal`, z-index 13000) and the RGUKT year question (`showEligibility`) wait while the first-run steps are pending or open (`welcomePending` flag in `docs/app.js`), then appear in that order (steps, college card, year question); before this they opened together and the card hid the About page. Every step has a **Back** button; Back on About restarts at the splash. Every panel and opened post also gets a top **"< Back"** (`.sheet-topback`, added in `renderCore()`).
- **CSP** (meta tag in each page): no inline scripts and **no inline `style=` attributes** in markup; set styles via classes or `applyStyle`. Allowed hosts are listed in `index.html`.

- **Sign-up gate (v487, on-demand since v491)**: `showAuthGate()` in `docs/app.js`. `requireSignup` in `docs/config.js` is `"post"` (default: anyone can browse, use Loopy AI and Loop Bot; the card appears only when someone posts, answers or shares, via `guard()` around `store.set/setIn/update` for the post collections, with a "Not now" button), `"boot"` (blocks everyone at the door after the welcome steps) or `false`. To post, one must create an account with e-mail + password (10+ characters, letters and numbers), verify the e-mail link, and verify the e-mail link. A mobile number with an SMS code (Firebase Phone Auth, invisible reCAPTCHA) is built but OFF (`requirePhone: false` in `docs/config.js`) because SMS needs the paid Blaze plan; with it off, never set `settings/posting.strongAuth` (it demands a phone number). Use `verifiedPosting` for e-mail-only enforcement. Anonymous users are linked, so their posts stay theirs. Server side, the admin switch `settings/posting.strongAuth = true` (set in the Firebase console) makes `firestore.rules` (posting) and the `askAI` function require a verified e-mail AND a mobile number. Turn it on only after the app with the gate is live and the Firebase console steps are done (enable Email/Password and Phone, allow SMS region India). Rules tests: `cd tests/rules && npm install && npm test`.

- **Digital Logic Design study page (v491)**: tapping the "Digital logic" tile in Loopy AI opens `dldHub()` (`DLD_UNITS` in `docs/app.js`): six official RGUKT units (course 23EC2102: I Number systems, logic gates and Boolean algebra; II Combinational circuit design; III Latches and flip-flops; IV Counters and shift registers; V Decoders, multiplexers, encoders and PLDs; VI Memory, programmable devices and digital system design) plus a "Beyond the syllabus" unit, mapping all 121 "Digital electronics" packs (v495 added 26 from the RGUKT unit reference PDFs: latches and flip-flops, counters, shift registers, multipliers, PLDs, cascading decoders; 14 more from Brown & Vranesic chapter 6 on synchronous sequential circuits: FSM structure, design steps, state diagram/table, state assignment, one-hot, Mealy vs Moore, Verilog Moore and Mealy FSMs, serial adder, state minimization, incompletely specified FSMs, counter design, arbiter, register swap; earlier: 41 original + 13 from Brown & Vranesic chapter 3 + 17 from chapter 4 and the end of chapter 3: floating-point, BCD addition, multiplexer synthesis, Shannon, decoder trees, priority encoders, comparator, Verilog conditional/if-else/case/for/operators/generate/ALU; chapter 3 topics were: signed numbers, 2’s complement rule, ripple-carry, adder/subtractor, overflow, carry-lookahead and hierarchical lookahead, radix complement, worked SOP/POS with don’t-cares, LUTs, Verilog vectors and modules), each of the six official units also has a **Practice questions** button (`dldPractice()`, data in `docs/dld-questions.js` `DLD_Q`: 2, 3 and 7 mark questions with model answers written from the RGUKT unit question banks, 122 in total; answers use ′ for complement and were checked by hand/script), progress kept in localStorage `dd-dld-seen`, Start/Continue button, topics open directly at Standard (or Brief) size via `bs.autoSize`.

- **Loopy AI search engine (v498)**: `docs/brain-search.js` (`makeSearch`) ranks all knowledge packs by weighted word overlap (title, keys, text), repairs spelling, joins/splits words (flipflop, flip flop) and expands short forms (ff, mux, fsm). `brainPacksMod` in `docs/app.js` asks it first (`best(q).sure`), then the old exact key-phrase match. Offline test: title queries 100%, typos 98%, no-space 92%, and none of 16 unrelated questions matched. Pack keys must be unique **after normalising** (hyphens and punctuation), `tests/packs.test.mjs` checks this. Pack results now also show "Exam in bullets" and "Practice questions on this topic" (from `dld-questions.js`), and the PDF/JPG sheet has a **Slides (PowerPoint)** option (`docs/pptx-lite.js`, a tiny zip + XML writer, checked with python-pptx and LibreOffice).

- **Legal pages (v499)**: Terms of Use and Privacy Policy only. The Refund Policy page was removed at the owner's request (Razorpay asks for a refund/cancellation policy at business approval, so it may need to come back as a section inside the Terms); Terms still say payments are final except where the law requires it.
- **First-run About page**: Continue is ignored for the first 3 seconds after the About page appears (v499), on top of the strict scroll/checkbox rule.

- **Student branch (v500)**: each student picks a branch once (`showBranchPicker()`, saved in localStorage `dd-branch`; `"*"` = "not listed, show everything"). The Doubts feed shows only doubts whose subject belongs to that branch (via `DEPT_MAP`, so the branch is **not stored on the post** and firestore rules need no change) plus common subjects and the student's own doubts; admins see everything. Filtering happens where the doubts arrive (`state.doubtsAll` raw, `state.doubts` filtered via `applyBranchFilter()`), so counts and search follow. The branch chips, the Ask form's subject list and a "Change branch" button follow the same choice. This is a view filter, not security: the data is still readable by every member of the college.

## Key decisions
- Static site, no framework or bundler, to keep it free and easy to host.
- Domain moved from `thecampusloop.co.in` to **loopybrains.com**. Old domain and `vijay462462.github.io` stay in CORS and API-key allow-lists. Repo was renamed `rgukt-spark` → **`loopybrains`** (old Pages URL may not work).
- App Check provider is `enterprise` because the Firebase apps are registered with Fraud Defense. Enforce only after 3 to 5 days of clean traffic (see next steps).
- Firebase Android JSON must use `android_client_info` (not `android_info`) or Gradle fails with "No matching client found".
- Loopy Search desktop fix: IntersectionObserver uses the viewport (not the scroll container) plus a rAF fallback; flex-column layout only applies via `:has(.bsc-hero)`.
- **Never delete Google Cloud API keys; edit their website restrictions instead** (must include loopybrains.com, www, and the old domains).
- Rename scope: user-facing text only. Left unchanged on purpose: Android package id, Firebase project id, old-domain allow-lists, calendar PRODID/UIDs, and old concept files in `docs/brand/`.
- Security posture is documented in `SECURITY.md` (rules deny by default, payments verified server-side, rate limits, CORS limited, no secrets in the repo, `npm audit` clean). Secrets live only in `firebase functions:secrets:set` and the GitHub secret `GOOGLE_SERVICES_JSON`.

## Working method (how work has been done here)
- Develop on a branch named like `claude/<name>` from the latest `origin/main`; open a PR; the owner says "merge #N" and the PR is **squash-merged**. Branches whose PR was merged are reset to `origin/main` and force-pushed with `--force-with-lease`. Do not open PRs or merge unless asked.
- Before committing run `bash scripts/check.sh` and, for `docs/app.js`, `node --input-type=module --check < docs/app.js`; for functions `node --check functions/index.js`.
- Visual checks: serve `docs/` with `python3 -m http.server 8765` and drive headless Chromium (`/opt/pw-browsers/chromium`, Playwright from `/opt/node22/lib/node_modules/playwright`), blocking non-localhost requests. Pre-set `localStorage`: `dd-college=rgukt`, `dd-welcome-done=1`, `dd-name`, `dd-simple=false`, `dd-tools-open=1`; pick the year in the `#rgElig` dialog. **Firebase is blocked offline, so posts, counts and sign-in cannot be tested this way.**
- Do not run `pkill -f <name>` with a pattern that appears in your own command line (it kills the shell).
